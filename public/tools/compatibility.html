Где и на чём это проверено

Только то, что реально гоняется в CI. Три джобы — Linux на JDK 21, Linux на JDK 17 и Windows на JDK 21 — прогоняют полный набор тестов, включая каждый формат выдачи. macOS в CI нет: там прогон ручной, и это честно помечено, а не закрашено зелёным.

что делает CI

build · ubuntu-latest · JDK 21

Полный ./gradlew build: тесты, fat jar, смоук собранного jar, демо-прогон 17/17, предрелизная проверка, публичный аудит снимка, смоук потребителя на JDK 17 и живой REST.

  • 912 тестов
  • 19 эндпоинтов проверяются live

build-jdk17 · ubuntu-latest · JDK 17

Тот же ./gradlew build, но на JDK 17 — страховка от случайного API из 21. Все модули собираются с --release 17.

  • байткод 61
  • весь API поднят на 17

windows · windows-latest · JDK 21

Сборка и тесты на Windows: пути, кодировка консоли, PowerShell-скрипты и gradlew.bat. Ловит то, что Linux прощает.

  • CRLF и cp866
  • пути и gradlew.bat

Docker · сборка образа

На PR собирает обе платформы без публикации и прогоняет контейнер; на теге — публикует amd64 и arm64.

  • smoke: /actuator/health
  • теги latest и версия

как проверить у себя

# полный набор тестов — то же, что гоняет CI
./gradlew build

# весь предрелизный контур: тесты, jar, демо, REST, потребитель
./tools/verify-all.ps1 -Fresh -Strict      # Windows
./tools/verify-all.sh  --fresh --strict    # Linux / macOS

# только интересующий формат
./gradlew :validum-core:test --tests "*CsvForExcelTest*"
java -jar validum.jar generate individual --seed 42 --format sql --dialect postgres
Свой JDK или своя ОС? Мы собираем и тестируем на 17 и 21; для других версий гарантий нет, но проверка занимает один прогон ./gradlew build — он и есть критерий. Если JDK новее 21, Gradle предупредит о deprecated-фичах, а не упадёт.

Сверено 20.11.2026 с .github/workflows/ci.yml (релиз 0.7.0, 912 тестов). Значения «не гоняется» означают, что проверки нет в CI — это не заявление о неработоспособности. Форматы: json, json-array, json-nested, csv, csv-semicolon (он же csv-excel), sql с диалектами postgres / oracle / mysql, набор set с четырьмя файлами и откатом.
